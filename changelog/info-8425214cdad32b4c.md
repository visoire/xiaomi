### 2026-09-20 - bw-flasher 0.7.1 upgrade & reliability overhaul

**Upstream upgrade from bw-flasher 0.7.0 → 0.7.1 & backend fixes:**

- **Plaintext LEQI support (5 Plus)**: `LeqiFlasher` now includes `is_plaintext_leqi_body()`
  and `embedded_crc_ok()` to dynamically detect unencrypted MCU firmware bodies (e.g., Xiaomi 5 Plus)
  and safely skip strict trailing CRC-16 checks.
- **Header tag parsing**: `detectFirmwareType()` and `parseHeaderFirmwareSize()` now inspect
  authoritative `EU1\0` header tags and uint16 body sizes at offset `0x0A` - `0x0E`.
- **Flasher "Test Connection" button**: Enabled immediately after serial port connection in Step 1,
  even before a firmware file is loaded. Probes controller via LEQI `DeviceInfo` and Brightway `get_ver`
  to display controller model, firmware version, and region.
- **WebSerial disconnect cleanup**: `WebSerialAdapter.disconnect()` now cleanly releases the stream
  reader lock (`_reader.releaseLock()`) before closing the port, preventing reconnect freezes.
- **Python auto-discovery**: Added `resolve_python_binary()` in `inc/functions.php` to locate Python 3
  across environment variables, Windows AppData, Program Files, system PATH (`where.exe`), and virtualenvs.
- **Command execution security & stability**: Refactored `patch.php` and `prepare.php` to pass arguments
  as structured arrays to `proc_open()`, preventing Windows `cmd.exe` shell quoting/escaping failures.
  Captured `stderr` stream directly for comprehensive error reporting.
- **Local tmp directory fallback**: `PATCHER_TMP` and `SETUP_TMP` now verify write permissions and
  automatically fall back to local `tmp/` directories to prevent system temp folder access issues.
- **Rate limiting exemption**: Local development / testing IPs (`127.0.0.1`, `::1`) are now exempt
  from rate limiting in `checkRateLimit()`, eliminating spurious HTTP 429 errors during testing.
- **Reference package deployment**: Upgraded `xiaomi/bw/bw-flasher-0.7.1` from `xiaomi/new/bw-flasher-0.7.1`
  (backup retained in `new/old/bw-flasher-0.7.0`). All unit tests passing.

### 2026-08-28 - bw-flasher 0.6.2 port + 6th generation support

**Web flasher port (from bw-flasher 0.6.2):**

- **EU1 header parsing**: LEQI firmware body size is now read from the image
  header (uint16 LE at offset 0x0E when `EU1\0` tag at 0x0A). Falls back to
  legacy AA-padding detection for files without the tag.
- **Embedded CRC-16 validation**: Firmware body carries a CRC-16 (poly 0x8005,
  input/output bit-reversed) in the last two bytes. Files with mismatched CRC
  are rejected before any serial traffic.
- **DeviceInfo connection test**: `testConnection` now sends command 0x02
  (DeviceInfo, read-only) instead of 0x03 (firmware update start). Reports
  controller firmware version and region.
- **Variable-length serial reader**: `_readLeqiResponse` accepts `expectedLen`
  parameter (default 7). Supports 17-byte DeviceInfo replies. Early-breaks
  after 5 bytes when the line goes quiet (20 ms).
- **UI button gating**: Both Test and Flash buttons require a valid firmware
  file. Previously Test could run without firmware or default to Brightway.
- **Raw buffer split**: `processFirmware` returns `{data, raw}`. LEQI flashing
  uses the untrimmed buffer so header and CRC remain intact.
- **Firmware info display**: New Body Size and Size Source rows in the firmware
  info panel for LEQI files.
- **i18n**: 6 new keys in en/de/pl: `js_fw_crc_fail`, `js_fw_crc_ok`,
  `js_dev_info`, `js_dev_region`, `fw_bodysize`, `fw_sizesource`.
- **uint16 guard**: `loadFirmware` throws if declared body size exceeds 0xFFFF

- **set_serialnumber.py**: Standalone CLI script (command 0x97) copied to

## Python venv (patcher + setup wizard)

The patcher and guided-setup backend require Python 3 with three packages:
`keystone-engine`, `capstone`, `crcmod`.

A dedicated venv lives at:

    /var/www/html/visoire/xiaomi/venv/

Both `patcher/config.php` and `setup/config.php` are already configured to use:

    PYTHON_BIN = /var/www/html/visoire/xiaomi/venv/bin/python3

### Re-create / update the venv

```bash
# 1. Make sure python3.11-venv is installed (only needed once on Debian/Ubuntu)
apt install -y python3.11-venv

# 2. Create (or recreate) the venv
python3 -m venv --clear /var/www/html/visoire/xiaomi/venv

# 3. Install the required packages into the venv
/var/www/html/visoire/xiaomi/venv/bin/pip install keystone-engine capstone crcmod

# 4. Verify
/var/www/html/visoire/xiaomi/venv/bin/python3 -c "import keystone; import capstone; import crcmod; print('OK')"
```

### Test the patcher CLI manually

```bash
cd /var/www/html/visoire/xiaomi/patcher

/var/www/html/visoire/xiaomi/venv/bin/python3 bwpatcher_cli.py \
  mi4 \
  /var/www/html/visoire/xiaomi/mcu/ada2fc4bdfc90b1e1e3562f0e0a453c7_mcu_dreame.scooter.t2201.bin \
  /tmp/test_out.bin \
  sls=25.0,chk

# Expected JSON output: {"ok": true, "model": "mi4", ...}
```

## Firmware files (MCU folder)

All stock firmware binaries now live inside their own model sub-folder under:

    /var/www/html/visoire/xiaomi/mcu/fw/<slug>/

Each sub-folder contains:
- One `.bin` stock firmware binary (filename includes the MD5 hash prefix)
- One `.png` scooter image (used by the patcher/setup UI - no CDN needed)

The master firmware metadata file (`data.json`) is at:

    /var/www/html/visoire/xiaomi/mcu/fw/data.json

This is the flat array format from mi-fw-info (GitHub: argusblack/mi-fw-info).

| Slug | Model ID | Manufacturer | Filename |
|---|---|---|---|
| mi4 | dreame.scooter.t2201 (Mi 4) | Brightway | `fw/mi4/ada2fc...bin` |
| ultra4 | dreame.scooter.p2301 (Mi 4 Ultra) | Brightway | `fw/ultra4/083efd...bin` |
| mi4lite | navee1.scooter.t2210 (Mi 4 Lite) | Brightway | `fw/mi4lite/031db3...bin` |
| mi4pro2nd | xiaomi.scooter.t2336 (Mi 4 Pro 2nd Gen) | Brightway | `fw/mi4pro2nd/83ca1d...bin` |
| mi5 | xiaomi.scooter.0005 (Mi 5) | Brightway | `fw/mi5/107558...bin` |
| mi5pro | xiaomi.scooter.5pro (Mi 5 Pro) | Brightway | `fw/mi5pro/aabaad...bin` |
| mi5max | xiaomi.scooter.5max (Mi 5 Max) | Brightway | `fw/mi5max/370dba...bin` |
| mi5elite | xiaomi.scooter.elite (Mi Elite) | LEQI | `fw/mi5elite/signed_d237...bin` |
| mi6 | xiaomi.scooter.6 (Mi 6) | LEQI | `fw/mi6/7e6e02...bin` |
| mi6lite | xiaomi.scooter.6lite (Mi 6 Lite) | LEQI | `fw/mi6lite/34da31...bin` |
| mi6pro | xiaomi.scooter.6pro (Mi 6 Pro) | LEQI | `fw/mi6pro/` (not yet available) |

When a new firmware version is released:
1. Add the new `.bin` to the appropriate slug folder (e.g., `fw/mi4/`).
2. Update `fw/data.json` with the new firmware record (or let the GitHub cron sync handle it).
3. Remove the old `.bin` from the slug folder.

Note: The `versions_cache.json` (written by the cron `fetch_versions.php`) is at:

    /var/www/html/visoire/xiaomi/mcu/fw/versions_cache.json

## Ultra vs Ultra 2 note (important)

The **Xiaomi Electric Scooter 4 Ultra** (EU) and **Xiaomi Electric Scooter 4 Ultra 2** (DE) share the same hardware and MCU model ID (`dreame.scooter.p2301`). The only difference is that the DE (Ultra 2) firmware has slightly worse acceleration due to German regulations.

**bw-patcher works with both.** Always select **Scooter 4 Ultra** when patching or flashing - the result is identical for both variants. This note is also visible in the hardware FAQ at `/xiaomi/hardware/`.

## set_serialnumber.py (optional tool)

A standalone Python CLI script at `flasher/scripts/set_serialnumber.py` implements
command 0x97 to write a 19-character product serial number to the BLE module NVM
(RTL8762C). **This is NOT part of the web flasher UI** - it targets the BLE module,
not the motor controller, and performs a persistent write with no documented undo.

Usage (requires pyserial):
```bash
pip install pyserial
python3 flasher/scripts/set_serialnumber.py /dev/ttyUSB0 "0539370000000ABCDEF" -v
```

Use `--generate` to preview the packet without sending:
```bash
python3 flasher/scripts/set_serialnumber.py --generate "0539370000000ABCDEF"
```

## Permissions check (web server)

PHP calls the Python venv binary via `proc_open`. Make sure:

```bash
# The web server user (www-data) can read the mcu folder and venv
chown -R www-data:www-data /var/www/html/visoire/xiaomi/venv/
chown -R www-data:www-data /var/www/html/visoire/xiaomi/mcu/

# The temp directory must be writable (it is by default: /tmp)
ls -la /tmp
```
